the cross-target error-kind divergence on deep recursive CTEs. See
`spec/sql-grammar.spec.md` § "Phase 9h" and
`tests/cross-build/phase9h-harness.md`.

## Findings

### Rust SIGABRT cluster — **RESOLVED**

Both Bug A (INSERT VALUES bare identifier) and Bug B (SELECT
unresolved column under GROUP BY) from 2026-04-21 are closed. The
Phase 9h spec pin requires every ColumnRef-lowering site to surface
a structured `ENGINE_ERROR` on resolution failure. Three call sites
in `src-rust/src/compiler.rs` have been patched:

- `compile_expression_scoped::Expression::ColumnRef` — the INSERT
  VALUES and no-FROM entry points.
- `compile_expression_scoped::Expression::QualifiedColumn` — the
  qualified-ref fallback on local/outer miss.
- `compile_expr_joined::Expression::ColumnRef` /
  `Expression::QualifiedColumn` — the joined-scope path.

None of those now panic on unresolved names; all surface a
structured condition per the Phase 9h table.

### Recursive CTE error-kind divergence — **RESOLVED**

Bug C closed. `src-rust/src/engine.rs::run_with_cte` now detects the
self-reference at CTE-materialize time and raises
`RUNTIME_RECURSIVE_CTE_LIMIT` directly when the binding's body
mentions the CTE's own name. This matches `leap-c`'s condition
kind exactly for the fuzz reproducer:

```
WITH RECURSIVE c(n) AS (SELECT 1 UNION ALL SELECT n+1 FROM c WHERE n < 1000000)
SELECT COUNT(*) FROM c;
```

Both targets now emit `ENGINE_ERROR RUNTIME_RECURSIVE_CTE_LIMIT`
with field `cte: "c"`. The `fuzz_exec` binary was also rerouted
through `execute_sql` so the CTE dispatcher fires — previously it
called `compile()` directly and bypassed the engine-level CTE
handler entirely. The fuzz-harness spec
(`tests/fuzz/harness-spec.md` § "Engine-level pipeline pin") now
documents this requirement.

- No Linux cross-validation. macOS arm64 only. Publication claims
  still wait on Linux.
- No AFL++ / cargo-fuzz coverage guidance. The 2026-04-21 mutator
  methodology applies verbatim; a corpus-guided follow-up remains a
  future campaign.
- No re-run of the file-format roundtrip matrix. Phase 9h is SQL-
  path-only; the file-format work is orthogonal and the 2026-04-21
  matrix (900/900 byte-equivalent) stands.

## Reproducibility

```
python3 tests/fuzz/sql/mutator.py \
  --harness src-rust/target/release/fuzz_exec \
  --seeds tests/fuzz/corpus/sql/valid \
  --out /tmp/fuzz_post_rust \
  --log tests/fuzz/results/2026-04-23-sql-exec-rust-phase9h.log \
  --duration-s 600 --seed 14

python3 tests/fuzz/sql/mutator.py \
  --harness src-c/bin/fuzz-exec \
  --seeds tests/fuzz/corpus/sql/valid \
  --out /tmp/fuzz_post_c \
  --log tests/fuzz/results/2026-04-23-sql-exec-c-phase9h.log \
  --duration-s 600 --seed 13
```

Both runs must report `crashes=0 panics=0 timeouts=0` in their final
summary line. Any regression on either line indicates the Phase 9h
fix has been partially reverted; the mutator's deterministic seed
will surface the identical reproducer shapes (`INSERT INTO t VALUES
(<bare-ident>)` or GROUP BY over an unresolved column) inside the
first ~30 k inputs.
